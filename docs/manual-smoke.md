# Ручной smoke-чеклист SkipNet / Manual smoke checklist

Документ из `REFACTOR_PLAN.md` (T0.5). Прогоняется **перед каждым релизом** и в PR,
затрагивающих hosts, DoH, Zapret, TgWs, обновления, автозапуск, трей или выход.

## Контексты прогона

Установленная сборка содержит манифест
`requestedExecutionLevel: requireAdministrator`, поэтому «обычный запуск без
администратора» для неё невозможен. Вместо этого используются реальные
контексты:

| Контекст | Как получить | Что проверяет |
| :--- | :--- | :--- |
| **Установленная (elevated)** | NSIS `SkipNet_x64.exe`, UAC подтверждён | Штатный путь: ACL на `resources/`, staging, автообновление, деинсталляция |
| **Portable** | Распакованный `SkipNet_x64-portable.7z`; данные в `<папка exe>\data` | Отдельный профиль, отсутствие uninstaller и автообновления, отсутствие защиты от same-user |
| **AV-locked hosts** | На время шага удерживать `hosts` заблокированным (антивирус, редактор с блокировкой, `handle.exe`) | Ретраи `rename`, отсутствие потери настроек и «половинчатого» блока |
| **UAC-cancelled (manifest-stripped)** | Сборка без `requestedExecutionLevel: requireAdministrator`, запуск обычным пользователем, отмена UAC при записи hosts | Приложение не падает и не пишет hosts, показывает причину |

Окружение: Windows 11 (актуальные обновления), чистый профиль
`%APPDATA%\skipnet` (для portable — пустой `<exe>\data`), собранный артефакт из
`pnpm build:win`.

## Заполнение

- `PASS` / `FAIL` — итог сценария в конкретном контексте; `н/п` — контекст
  неприменим. Для `FAIL` приложить лог из вкладки Logs и, если нужно,
  скриншот.
- Версия, дата и подпись заполняются один раз на прогон (таблица в конце).
- Сценарий считается закрытым, только если он PASS во **всех применимых**
  контекстах, либо явно отмечено, что контекст неприменим.

## Сценарии

### 1. hosts: включить → применить → откатить

| | |
|---|---|
| **Шаги** | 1. Открыть «Редактор hosts». 2. Включить один DNS-сервис (например, Discord) и один hosts-сервис (`Telegram`). 3. «Применить». 4. Проверить `C:\Windows\System32\drivers\etc\hosts`. 5. «Откатить». 6. Проверить hosts и `hosts-state.json`. |
| **Ожидаемо** | Между `# --- SkipNet hosts editor BEGIN ---` и `END` ровно записи выбранных сервисов; вне блока файл не изменился. При откате managed-блок удалён, остальные строки сохранены байт-в-байт. Перед записью создан бэкап `hosts-backups/hosts-<stamp>.bak`; при ошибке записи блок не остаётся «половинчатым». |
| **Установленная (elevated)** | PASS / FAIL: |
| **Portable** | PASS / FAIL: |
| **AV-locked hosts** | PASS / FAIL: при удержании файла запись повторяется, затем показывает понятную ошибку; `hosts-state.json` не теряет выбор; после снятия блокировки повторное «Применить» работает. |
| **UAC-cancelled (manifest-stripped)** | PASS / FAIL: при отмене UAC hosts не меняется, приложение не падает и объясняет причину; повторный запуск от администратора применяет выбор. |

### 2. DoH refresh при медленной сети

| | |
|---|---|
| **Шаги** | 1. Включить несколько DNS-сервисов. 2. Ограничить сеть (`clumsy`: задержка 2–5 с или потери 30 %). 3. Нажать «Обновить адреса» (DoH refresh). 4. Во время прогона переключить сервис и снова выключить. 5. Дождаться завершения. |
| **Ожидаемо** | UI не блокируется: toggle и навигация отвечают < 200 мс. Повторный refresh отменяет предыдущий (пробы отменяются, в логе нет двух параллельных прогонов). По завершении обновлённые адреса записаны в `hosts-state.json` (`resolvedIps`, `resolvedAt`), hosts применён; при таймауте дедлайна hosts не перезаписывается «пустым» блоком. Мёртвые адреса не попадают в файл. |
| **Установленная (elevated)** | PASS / FAIL: |
| **Portable** | PASS / FAIL: |

### 3. Zapret: start → stop → 5× restart

| | |
|---|---|
| **Шаги** | 1. Выбрать стратегию и нажать Start. 2. Stop. 3. Пять раз подряд нажать Restart с интервалом ~1 с. 4. В Process Explorer / `tasklist` посчитать `winws.exe`. 5. Нажать Stop и выйти из SkipNet. |
| **Ожидаемо** | После 5 рестартов ровно **один** процесс `winws.exe`, порт не залип. После Stop и выхода SkipNet ни `winws.exe`, ни драйвер WinDivert не остаются в памяти; повторный Start после выхода работает. Статус в UI не залипает в `starting`/`stopping`. |
| **Установленная (elevated)** | PASS / FAIL: |
| **Portable** | PASS / FAIL: процессы запускаются из `<exe>\resources`, данные — в `<exe>\data`. |

### 4. TgWs: ссылка `tg://`, освобождение порта, секрет в логах

| | |
|---|---|
| **Шаги** | 1. Включить TgWs (порт по умолчанию 1443). 2. Открыть сгенерированную `tg://proxy?...` ссылку. 3. Открыть вкладку Logs. 4. Stop. 5. Проверить, что порт 1443 свободен (`netstat -ano \| findstr :1443`). |
| **Ожидаемо** | Telegram подключается через прокси. Ссылка открывается, секрет работает после перезапуска приложения. В логах **нет** 32-hex секрета (ни в `--secret ...`, ни в `secret=...`, ни в `tg://`-ссылке): только `secret OK (len=32)`. После Stop порт свободен, процесса `TgWsProxy_windows.exe` нет. |
| **Установленная (elevated)** | PASS / FAIL: |
| **Portable** | PASS / FAIL: секрет и порт сохраняются в `<exe>\data\config.yaml`. |

### 5. Обновление приложения и сохранность настроек

| | |
|---|---|
| **Шаги** | 1. На предыдущей версии (например, 1.5.0) дождаться баннера следующей версии (или нажать «Проверить обновления»). 2. Запомнить: секрет TgWs, выбранную стратегию Zapret, тему, автозапуск, настройки трея, включённые hosts-сервисы. 3. Установить обновление. 4. Проверить `%APPDATA%\skipnet\config.yaml` и `hosts-state.json` после запуска новой версии. |
| **Ожидаемо** | Установка идёт по тегу из GitHub, digest скачанного ассета проверен. После апдейта версия новая, все перечисленные настройки и секрет на месте (ссылка `tg://` не сломалась), hosts применяется без повторной настройки. |
| **Установленная (elevated)** | PASS / FAIL: |
| **Portable** | PASS / FAIL: обновление **отклоняется** с понятным сообщением, установщик не запускается, `<exe>\data` не меняется. |

### 6. Негатив: подменённый sha256 / отсутствующий digest

| | |
|---|---|
| **Шаги** | 1. В тестовой сборке с подменённым ответом `api.github.com` (или через локальный прокси) подать ассет с неверным digest. 2. Повторить с релизом, у которого digest отсутствует. 3. Нажать «Установить». 4. Дополнительно: вручную добавить в `update-cache-app.json` поля `assetUrl`/`digest` и повторить установку. |
| **Ожидаемо** | Установка **отклонена** до запуска `.exe`: понятное сообщение («Контрольная сумма не совпадает» / «Отсутствует контрольная сумма»), в логе запись без выполнения инсталлятора. Приложение остаётся работоспособным, повторная проверка обновлений не падает. Правка кеша не влияет на URL/дайджест: main резолвит их заново через API. |
| **Установленная (elevated)** | PASS / FAIL: |

### 7. Автозапуск: Task Scheduler, `&` и кириллица

| | |
|---|---|
| **Шаги** | 1. Установить SkipNet в папку с `&` и кириллицей (например `C:\Пользователь\R&D\SkipNet`). 2. Включить автозапуск. 3. Открыть Task Scheduler → задача `SkipNetAutoStart`, проверить XML/действие. 4. Перезалогиниться. 5. Выключить автозапуск и проверить, что задача/запись Run удалены. |
| **Ожидаемо** | Задача создаётся без ошибок, `&` экранирован в XML, кириллица сохранена, путь и `USERDOMAIN\USERNAME` корректны; после входа SkipNet стартует из папки с `&` и кириллицей. При выключении удалены `SkipNetAutoStart`, legacy-задачи `SlipgateAutoStart`/`Slipgate Auto Start` и Run-значение `Slipgate`; автозапуск больше не срабатывает. |
| **Установленная (elevated)** | PASS / FAIL: |
| **Portable** | PASS / FAIL: задача указывает на portable `SkipNet.exe`, данные остаются в `<exe>\data`. |

### 8. Трей: скрыть/показать и выход «только свои процессы»

| | |
|---|---|
| **Шаги** | 1. Включить трей в настройках. 2. «Скрыть в трей» и вернуть окно из меню трея. 3. Запустить вручную вторую копию `winws.exe` из другой папки (или `TgWsProxy_windows.exe`). 4. Выйти из SkipNet. 5. Проверить `tasklist`. |
| **Ожидаемо** | Окно скрывается/показывается из трея, меню и горячие клавиши работают. При выходе завершаются **только** процессы, запущенные этим экземпляром SkipNet (по PID/пути); чужая копия `winws.exe` продолжает работать. Повторный запуск SkipNet после выхода чистый (single-instance не блокирует). |
| **Установленная (elevated)** | PASS / FAIL: |
| **Portable** | PASS / FAIL: чужая установленная копия не затрагивается. |

### 9. Деинсталляция: блок hosts и только свой профиль

| | |
|---|---|
| **Шаги** | 1. Включить 2–3 hosts-сервиса и применить. 2. Закрыть SkipNet. 3. Создать второго локального пользователя и файл-маркер в его `%APPDATA%\skipnet`. 4. Запустить деинсталлятор. 5. Проверить `hosts`, профиль текущего пользователя, профиль второго пользователя и junction в профиле. |
| **Ожидаемо** | Managed-блок SkipNet удалён из `hosts`, остальные строки сохранены; бэкап `hosts.skipnet-backup-<timestamp>` рядом с `hosts` остаётся способом восстановления. Профиль **текущего** пользователя очищен; `%APPDATA%\skipnet` второго пользователя и маркер на месте; обхода `C:\Users\*` и перехода по junction нет. Если PowerShell недоступен, деинсталлятор продолжает работу и сообщает, что блок hosts не удалён. |
| **Установленная (elevated)** | PASS / FAIL: |
| **Примечание** | При удалении «через плечо» очищается профиль администратора, запустившего деинсталлятор; это принятый риск, а не ошибка. |

### 10. Writable-каталог: подмена payload и манифеста

| | |
|---|---|
| **Шаги** | 1. Установить SkipNet в пользовательский каталог, например `C:\Tools\SkipNet`. 2. Проверить ACL: `icacls C:\Tools\SkipNet\resources`. 3. Обычным (не elevated) процессом попытаться заменить `resources\zapret\bin\winws.exe` и дописать строку в `resources\binaries.sha256`. 4. От администратора заменить только payload. 5. Запустить Zapret. 6. Повторить для portable-копии. |
| **Ожидаемо** | В установленной сборке наследование ACL снято: Administrators/SYSTEM — полный доступ, Users — чтение и запуск; запись обычным пользователем отклоняется. Замена только payload (или только манифеста) приводит к отказу запуска с ошибкой целостности. Замена payload **вместе** с манифестом не детектируется: манифест подтверждает самосогласованность, а не подлинность; это принятый риск. В portable оба файла доступны пользователю, поэтому подмена проходит — для защиты используйте установщик. |
| **Установленная (elevated)** | PASS / FAIL: |
| **Portable** | PASS / FAIL: замена только payload должна приводить к отказу запуска; замена payload **вместе** с манифестом проходит — это принятый риск, не регрессия. |

### 11. Portable и установленная копии одновременно

| | |
|---|---|
| **Шаги** | 1. Запустить установленную копию. 2. Запустить portable `SkipNet.exe` из другой папки. 3. Включить TgWs в обеих (порт 1443). 4. Запустить Zapret в обеих. 5. Выйти из установленной копии. 6. Проверить `tasklist` и данные профилей. |
| **Ожидаемо** | Обе копии открываются: single-instance lock у каждой свой. Профили независимы: `%APPDATA%\skipnet` и `<portable>\data`. Вторая копия TgWs получает ошибку занятого порта и не убивает первую. У каждого экземпляра свой `winws.exe` из его `resources`. Выход из установленной копии завершает только её процессы; portable продолжает работать. |
| **Установленная + Portable** | PASS / FAIL: |

## Автоматический renderer smoke (Playwright, только локально)

`pnpm test:e2e` собирает `out/` (`electron-vite build`) и запускает
`test-e2e/app.spec.ts` через Playwright Electron. Проверяются только
read-only сценарии рендерера:

- главное окно и редирект на `#/home`;
- переходы по сайдбару `/hosts`, `/settings`, `/logs`, `/zapret` с проверкой
  заголовка страницы;
- отсутствие `pageerror` и `console.error` (allow-list только для известного
  шума Chromium/DevTools);
- непустой каталог сервисов на странице hosts (без apply/toggle);
- наличие переключателей автозапуска и трея в настройках (без кликов).

Изоляция: каждый запуск получает уникальный `--user-data-dir` в `os.tmpdir()`,
поэтому `%APPDATA%\skipnet` и single-instance lock реального приложения не
затрагиваются. Тестовый entrypoint `test-e2e/electron-main.cjs` загружает
настоящий `out/main/index.js`, но отключает только OS-интеграцию вне области
smoke-теста: регистрацию `skipnet://`/`tg-ws://`, `schtasks`, `reg`,
`sc start/stop/delete` и `taskkill`. Маркер
`resources/zapret/utils/check_updates.enabled` также остаётся без изменений.
Страница hosts читает реальный файл hosts (только чтение, без записи).
Запускайте из обычной non-admin консоли; UAC не требуется.

**Статус CI: локально.** Job в `.github/workflows/ci.yml` не добавлен:
стабильность GUI-сессии Electron на GitHub-hosted Windows runner и контекст
admin на runner'е не проверялись. `pnpm test:e2e` не заменяет этот чеклист:
он не нажимает apply/toggle/start/update и не проверяет UAC, hosts и
деинсталляцию.
