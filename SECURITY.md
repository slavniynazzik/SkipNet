# Безопасность SkipNet

Документ описывает поддерживаемые версии, порядок сообщения об уязвимостях,
модель угроз, гарантии релиза 1.5.0 и явно принятые риски. Технические детали
процессов и границ доверия — в [docs/ARCHITECTURE.md](./docs/ARCHITECTURE.md).

## Поддерживаемые версии

| Версия | Поддержка |
| :--- | :--- |
| **1.5.x** | Исправления безопасности и ошибок |
| **1.4.x и старше** | Не поддерживается; обновитесь до 1.5.x |

Исправления выпускаются только для актуальной ветки. Старые сборки не получают
патчей и не должны использоваться на машинах, где важна целостность обновлений.

## Как сообщить об уязвимости

Используйте **приватные GitHub Security Advisories**:

<https://github.com/slavniynazzik/SkipNet/security/advisories/new>

Не открывайте публичные issues для уязвимостей: это раскрывает проблему до
выпуска исправления. В обращении укажите версию SkipNet, сборку Windows, шаги
воспроизведения и логи без личных данных. Ответ даётся по возможности; сроки
не гарантируются.

## Модель угроз

Защита рассчитана на следующие сценарии:

| Угроза | Что означает |
| :--- | :--- |
| **Скомпрометированный renderer** | XSS или подмена загруженной страницы пытается вызвать привилегированные IPC-каналы, подсунуть URL/дайджест установщика или выполнить код с правами администратора |
| **Процесс того же пользователя без прав администратора** | Обычный процесс пытается подменить файлы в `%APPDATA%`, `%TEMP%`, portable-папке или `config.yaml`, чтобы приложение запустило его код с повышением прав |
| **Враждебное зеркало обновлений** | Зеркало (`gh-proxy.com`, `ghfast.top`) отдаёт свой JSON с чужим дайджестом или подменённый ассет |
| **Отравленный DNS/DPI** | Подмена ответов DNS или вмешательство провайдера при подборе адресов для hosts и при скачивании обновлений |
| **Правка файлов вручную** | Пользователь или вредоносный процесс меняет `config.yaml`, системный `hosts` или скачанный каталог сервисов |
| **Компрометация upstream-репозитория компонента** | Вредоносный релиз в стороннем репозитории Zapret или TgWsProxy |

## Что гарантирует 1.5.0

1. **Обновления fail-closed.** `verifyAsset`/`verifyDigest` требуют непустой
   `sha256:<64 hex>` и точный размер; отсутствие, иной формат, несовпадение
   размера или хеша отменяют установку до записи и запуска.
2. **Метаданные только с `api.github.com`.** `fetchGithubApi` не использует
   зеркала и env-переопределения; в собранной сборке `SKIPNET_*` и
   `ELECTRON_RENDERER_URL` игнорируются (`devEnv`).
3. **Суммы только напрямую.** `SHA256SUMS.txt` скачивается
   `fetchReleaseAssetDirect` из того же релиза; зеркала к нему не применяются.
4. **Установка по тегу.** Рендерер передаёт только тег; main заново резолвит
   ассет по allow-list имён, а `assertExpectedReleaseTag` требует совпадения с
   последней проверкой.
5. **Staging только для администраторов.** Установщик пишется в
   `%ProgramData%\SkipNet\updates` с ACL Administrators/SYSTEM, перечитывается и
   повторно проверяется непосредственно перед `spawn`.
6. **Узкий preload и sandbox.** Включены `sandbox: true` и
   `contextIsolation: true`; мост отдаёт только `invoke`/`on` по frozen-списку
   `INVOKE_CHANNELS`/`EVENT_CHANNELS`.
7. **Доверие только своему кадру.** `isTrustedSender` требует top-level frame и
   точный путь `out/renderer/index.html` (или точный dev-origin); иначе вызов
   получает `{ ok: false }`.
8. **Схема конфига.** `validateAppConfigPatch` проверяет allow-list ключей, типы,
   enum и диапазоны до `deepMerge`; `__proto__`/`constructor`/`prototype`
   блокируются, `binaryPath`/`bundlePath` отбрасываются.
9. **Никаких исполняемых файлов из `%APPDATA%`.** `tgwsBinaryPath()` и
   `zapretBundleDir()` всегда указывают в `resources/`; `runtimeDir()` не
   используется для запуска.
10. **Манифест sha256.** `resources/binaries.sha256` покрывает каждый `.exe`,
    `.dll`, `.sys`, `.bat`, `.ps1` и `.bin`; проверка выполняется при сборке и
    перед каждым запуском компонента, неописанный файл — отказ.
11. **Редакция секретов.** `redactSecrets` в `appLog` (единая точка выхода)
    маскирует `--secret`, `secret=`, `tg://proxy?...secret=` и 32-hex-токены,
    включая строку спавна TgWs.
12. **Завершение только своих процессов.** PID и путь фиксируются при spawn;
    kill идёт через `taskkill /PID <pid> /T`, а поиск по имени — только fallback
    с проверкой пути внутри `resources/`.
13. **Системные утилиты по абсолютному пути.** `sysBin` берёт `taskkill`,
    `icacls`, `powershell` и `ipconfig` из `System32` и валидирует `SystemRoot`.
14. **Атомарная запись hosts.** Бэкап → state → temp + `fsync` + `rename` →
    перечитывание и сверка хеша → откат при расхождении.
15. **Деинсталлятор чистит только своё.** PowerShell-скрипт удаляет
    managed-блок; профиль чистится через `SetShellVarContext current`, без
    обхода `C:\Users\*` и перехода по junction.
16. **ACL на `resources/`.** NSIS снимает наследование и выдаёт
    Administrators/SYSTEM полный доступ, Users — чтение и запуск.

## Принятые риски

- **Сборки не подписаны.** Windows SmartScreen и антивирусы могут
  предупреждать при первом запуске. Проверяйте `SHA256SUMS.txt` вручную:
  `Get-FileHash .\SkipNet_x64.exe -Algorithm SHA256`.
- **Portable-ресурсы доступны на запись пользователю.** Манифест в portable
  режиме доказывает только самосогласованность файлов, а не их подлинность;
  для целостностной защиты используйте установщик.
- **Доверие к компонентам опирается на upstream.** Flowseal zapret и TgWs —
  источники доверия для своих сборок; их компрометация находится вне модели
  защиты SkipNet.
- **Зеркала могут отдавать байты ассетов.** Они не участвуют в метаданных и
  суммах, поэтому могут задержать или оборвать загрузку, но не подменить
  ожидаемый дайджест.
- **Деинсталляция «через плечо».** Over-the-shoulder удаление чистит профиль
  того администратора, который запустил деинсталлятор, а не исходного
  пользователя.
- **Очистка hosts при удалении требует PowerShell.** Если PowerShell
  недоступен, блок остаётся; резервная копия рядом с `hosts` остаётся
  способом восстановления.
- **Секрет TgWs виден в командной строке дочернего процесса.** Процессы того
  же пользователя могут прочитать argv; редакция логов не меняет argv.

## Что не защищено

- Локальный администратор или malware с правами администратора/root.
- Атакующий уровня ядра.
- Компрометация GitHub или upstream-репозиториев компонентов.
- Блокировка DoH/SNI: hosts не обходит DPI, а при недоступных DoH-серверах
  обновление адресов честно завершается без записи.

## Обработка данных

| Данные | Расположение |
| :--- | :--- |
| Настройки (`config.yaml`) | `%APPDATA%\skipnet\config.yaml`; в portable — `<папка exe>\data\config.yaml` |
| Состояние hosts (`hosts-state.json`) | `%APPDATA%\skipnet\hosts-state.json` (или `<exe>\data`) |
| Системный `hosts` | `C:\Windows\System32\drivers\etc\hosts`, managed-блок между маркерами SkipNet |
| Бэкапы hosts | `%APPDATA%\skipnet\hosts-backups\hosts-<stamp>.bak` (до 20) |
| Логи | `%APPDATA%\skipnet\logs\app-YYYY-MM-DD.log` |
| Кеш обновлений | `%APPDATA%\skipnet\update-cache-*.json`, только тег, версия, заметки и время проверки |

`config.yaml` содержит секрет TgWs (`tgws.secret`, 32 hex) и адрес Worker в
открытом виде. Не публикуйте файл целиком. Секрет также передаётся аргументом
`--secret` запущенному `TgWsProxy_windows.exe` (см. принятые риски).

Логи пишутся в JSONL, ротация — при 5 МБ на файл, старые файлы удаляются после
`maxLogDays` (по умолчанию 7 дней). Все строки проходят через `redactSecrets`
до записи и до отправки в интерфейс. В логах не должно быть секрета, `tg://`
ссылок с секретом и сырых 32-hex-токенов.

Сетевые обращения: `api.github.com` (метаданные релизов), `github.com` и
`objects.githubusercontent.com` (ассеты), зеркала (только байты ассетов),
`raw.githubusercontent.com` (каталог hosts), DoH-серверы Google, Cloudflare и
AdGuard (имена проверяемых доменов) и сервер списков сообщества.
